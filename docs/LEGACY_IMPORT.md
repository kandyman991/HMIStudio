## Implemented

`hmi_legacy_import::import_portable(&[u8])` returns an optional validated canonical `Project` and a deterministic `MigrationReport`. It has no file writes, device access, runtime commands or deployment behavior. Only explicit source versions 1–10 are recognized. The decoder rejects duplicate keys at every level, invalid UTF-8/JSON, oversize inputs (4 MiB), excessive nesting (serde JSON limit), more than 20,000 report leaves or paths exceeding 1,024 bytes. No archives are admitted by this API.

The initial mapping subset covers metadata, explicit startup screen, flat absolute screen dimensions, static labels with explicit text and geometry, visible flags, internal read-only variables with six scalar types and exact typed default values. Legacy Float fields are interpreted at binary32 precision. Source IDs retain valid noncolliding values or are allocated deterministic replacements; the project ID is derived from its input SHA-256, generated root IDs are identified in the ID map. For multi-screen projects explicit valid order is currently required (v5+); ambiguous equal z-index ordering is refused. Default locale is en because no source locale is declared in this subset. No visual fidelity claim.

The report records the input SHA-256, source version, importer version, RFC 6901 paths, disposition, code, severity, message, proposed canonical target and ID map. For well-formed admitted-size inputs, every leaf (including empty containers) is accounted for. If any finding is refused, **no project is returned**. Mapped findings on a refused import describe proposed transformations, not persisted output. Malformed or resource-limited inputs receive a root refusal instead of an unbounded leaf report. The report does not include arbitrary source values, but paths and ID mappings contain source key names/identifiers: keep reports local and review before sharing. No arbitrary source data is copied to extensions. Successfully mapped projects carry `hmiforge.idMap`; adaptive nodes also retain explicitly decoded geometry and validated z-index as inactive design metadata (B.3).

## Explicit remaining work

This is deliberately not full v1–v10 compatibility. Version-number coverage tests use the same supported synthetic subset, not all features introduced at each version. Full source semantic validation, remaining industrial/security semantics (see B.2 below), remaining graphical/layout/binding/enum semantics (see B.3), actions, alarms, assets and themes remain outstanding. Those inputs refuse rather than silently downgrade. Preserve-with-blocking semantics are not available until publishing/runtime refusal is integrated; no partial project is emitted. Revision bundle and runtime package readers with checksum/size/traversal verification, typed engineering import command, sidecar reports and UI integration are also outstanding. No acceptance or completion of REUSE-03 is claimed.
