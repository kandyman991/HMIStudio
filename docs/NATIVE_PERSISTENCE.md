# RUST-02C — Native project persistence (candidate)

Based on PR #6 merge `264ace7e47d3c16c21c8415875fb64db1bf7c1d0`. The existing engineering-core persistence implementation remains authoritative; this slice adds the desktop host boundary.

## Implemented

- Native Rust-owned Tauri dialog actions (New, Open, Save, Save As, Recover, Resolve untitled recovery, Exit); no webview-supplied paths or overwrite flags. Capabilities remain empty, including dialog and filesystem plugin permissions.
- Canonical .hmi.json project paths, one app-data recovery lock plus an OS advisory writer lock in each project sidecar. Persistent lock filenames are never unlinked; OS releases handles on process exit. Project switch obtains candidate lock before reading or releasing the previous lock.
- Reject symlink/reparse points in project paths, ancestors and sidecars/backups; Unix hard links rejected. Guarded filesystem revalidates each engine operation. Application recovery directory created with Unix mode 0700. Operates on trusted local directories, not a hostile filesystem sandbox: check/use races and directory replacement by other processes are not eliminated; network/cloud-synced filesystems are not validated.
- Save delegates to atomic staging, backups, conflict detection and validation. Save As refuses unrelated existing files and targets with recovery data. No force-overwrite UI; external modification/deletion requires a different filename or explicit discard/reopen. Core save warnings surfaced.
- Native worker autosaves dirty sessions every 30 seconds; no JS timer writes files. Autosave errors visible in status; the existing envelope is never overwritten at startup before explicit untitled recovery resolution. A crash before the next interval may lose un-autosaved edits. App-data recovery and named project recovery are separate; a deleted original can be recovered by selecting its sidecar autosave.meta.json.
- Native Yes/No/Cancel prompts protect dirty sessions during New/Open/Recover/Exit and OS close. Yes saves, No explicitly discards, Cancel preserves; failed/canceled saves block destructive transitions. Candidate parse precedes active session replacement and old recovery cleanup. Discarding candidate recovery is a separate explicit choice; if subsequent old-recovery cleanup fails, that candidate discard is not rolled back. A new session resets tabs and selection and increments host generation; stale-generation engineering edits rejected even if revisions overlap.
- No runtime deployment, PLC connectivity, project schema change, private source import or production acceptance.
