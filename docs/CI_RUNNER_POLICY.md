# CI runner and build policy

Public successor policy, not the legacy private repository's runner contract. CI-02 supersedes routine installer generation under D-006; D-008 still applies.

- Standard GitHub-hosted Windows/Linux runners only for public PRs; no private runners, pull_request_target, secrets or write tokens. Checkout exact PR head without persisted credentials. Review CI source changes independently.
- Desktop CI runs for every PR and main push, without workflow-level path filtering. The Required CI job is always evaluated and fails if classification or any applicable job fails/cancels or is unexpectedly skipped. Handoff snapshot remains separate and required by engineering policy. Never bypass either, applicable independent dependency checks or review.
- Classifier uses full Git history, merge-base diff for PRs and before/head diff for main pushes, NUL-delimited paths and no rename detection (both old and new paths checked). Missing base, unknown paths, other CI changes and manual dispatch force the full suite. Documentation-only means top-level Markdown, docs Markdown and handoff/state.json; run classifier regression tests and parse handoff JSON. No claim of comprehensive Markdown lint or link checking.
- The existing Desktop CI changes job always validates the roadmap schema, dependency and evidence rules, migration sources and generated views. The offline `roadmap/` directory, generated Markdown and the planner/roadmap regression files select this lightweight gate. Changes to other CI inputs, unknown paths, tags and manual dispatch retain full fallback. Combining roadmap and application paths retains every applicable application and packaging check.
- Frontend changes run locked npm install, UI tests, TypeScript and Vite build. Native code and crate changes also run Windows/Linux native tests; crate changes exercise all standalone crates on both platforms (fmt, Clippy, locked tests, rustdoc, model fixtures). This conservative dependency rule avoids skipping downstream native consumers. New crates must be included in discovery or explicitly registered and independently reviewed; preserve any additional dedicated tests/advisory checks, including the pending tag-engine audit in PR #7. Project-model and engineering-core workflows remain manual entry points; automatic tests are consolidated in Desktop CI.
- Installer generation/upload is limited to packaging-sensitive paths (Tauri config/manifests/build scripts/resources, icon, npm manifests/locks), full fallback, release tags v*, and explicit manual Desktop CI dispatch. Milestone acceptance requires manual dispatch at the exact accepted revision if not already packaged. Routine native tests are not release builds or install/launch acceptance. Release tags generate unsigned development installers only; release signing remains separate.
- To build installers: Actions > Desktop CI > Run workflow > choose branch/tag > Run workflow. Both Windows MSI and Linux DEB are generated; verify head SHA and download from that run. Development artifacts retained three days, not engineering memory.
- Superseded automatic runs are cancelled; manual runs use a separate concurrency group so they cannot cancel required PR checks. New manual runs supersede older manual runs on the same ref.
- Rust registry and dependency compilation caching uses pinned Swatinem/rust-cache v2.9.3 (d1527c8f67ef9af357290475d4af4b0fab8f12e0), with separate workspace/platform/profile keys, no Cargo binary cache, successful main pushes only for saves, PRs restore-only. npm cache via setup-node. Cache misses are normal; lockfiles and all selected checks remain authoritative. Review action supply chain and monitor cache quota; do not cache secrets or private dependencies.
- Commit lockfiles; require locked resolution and verify no lockfile drift. Review applicable dependency vulnerabilities/licenses independently; issue #4 remains open. Batch fixes; no repetitive reruns without evidence.
- Required-check transition: inspect repository branch protection/rulesets; configure Required CI plus snapshot (and any applicable independent gate). Existing required contexts must not be removed until replacement gate is validated. Connector could not inspect branch protection (403); owner/admin verification required if old matrix contexts are enforced. Never weaken enforcement to force a merge.
- Snapshot is read-only and never uploads artifacts or writes refs. Verify exact final PR head, live main and independent review. Skipped installer jobs mean not built, never passed.

## Review depth (owner-approved, 2026-11-25)

Use the AGENTS.md scope-based review policy: lightweight independent consistency review for evidence/documentation-only changes, full technical review for executable or control-changing changes and mixed/uncertain scope. Both require exact-head Required CI and Engineering handoff success and applicable dedicated checks. The reviewer verifies classification, evidence and authorization; no change to CI routing, installer triggers, security gates or acceptance criteria follows from a lighter review.

### Review cadence within draft milestone PRs (D-008 follow-up, 2026-11-27)

Routine draft slices need self-review, applicable tests and exact-head successful checks, not a new comprehensive independent review per slice. Batch independent technical review at the major milestone boundary before merge, with earlier risk-triggered review as defined in AGENTS.md. Existing independent pre-merge review, dependency audits, Required CI, handoff, installer and acceptance gates are unchanged. No workflow routing change.
