## Contract candidate

| Area | Proposed representation and required invariant |
| --- | --- |
| Version | Keep the committed v1 schema and fixtures immutable as historical contract; publish v2 schema under a new versioned filename when complete. Register explicit v1-to-v2 migration; accept v1, reject unsupported versions and duplicates. New v2-only keys in v1 must not accidentally be interpreted as authorized policy. |
| Drivers | Reuse existing SiemensS7 identifier (no duplicate S7 enum). Add a separate loopback declaration with no hardware access; do not auto-register physical drivers or connect on load. Driver-specific parameters are non-secret; secure-store refs only. |
| Write policy | Optional typed tag declaration for command kind, confirmation, critical, pulse duration, exact numeric limits and step, and explicit confirmation evidence flag; separate connection commissioningAllowed default false. Preserve display range separately. Never round integer limits through f64; fail closed on invalid or unrepresentable data. Model declarations do not authorize writes. Preserve existing simulation behavior. |
| Security | Typed permissions and roles with stable identifiers, anonymous role and auto-logout; permission refs on screens/nodes, global uniqueness and reference validation. No passwords/tokens or imported active trust. Unresolved/unsupported policy blocks publish, never grants access. |
| Actions | Typed startup navigation resolves current startup target; faceplate opens a reusable definition with typed parameters and validated references. No execution during import; retain existing transaction and event validation. |
| Enumerations | Typed discrete values, localized labels and optional color, exact equality and unique values; distinguish display maps from write limits. |
| Components | Industrial symbols use reusable definition library where semantically sufficient; extend catalog only for missing primitives/inputs with explicit property and binding contracts. No mock rendering or silent approximation. |
| Expressions | Contract-versioned read-only binding source; validate syntax, type and referenced tags/parameters, bounded evaluation; no I/O, writes, arbitrary code or unsafe coercions. Pin contract-1 behavior and compare against independently authored golden vectors before enabling; unsupported expressions produce blocking diagnostics. |

## Implementation order

1. Compatibility regression baseline (this slice). Existing model already includes SiemensS7, typed transforms, tag parameters, exact JSON integer handling and a migration registry. Current schema export and several fixture assertions are hard-coded v1; update consumers deliberately rather than changing the version constant alone.
2. Specify concrete serialized fields/types and contract-1 vectors against the authorized audit and read-only behavior reference. Implement industrial declarations, policy and security validation plus typed engineering commands. Preserve undo/redo, reference deletion/rewrite behavior and transaction rejection.
3. Add typed action, enumeration, component and expression contracts, validation and command coverage. Review downstream tag-engine, Tauri and frontend consumers; extend the reservation before touching paths outside the current scope. No runtime behavior or publishing claim.
4. Activate v2 only when the complete additive schema, v1 migration and generated schema tests agree; verify every existing fixture and all affected downstream builds, migration determinism, exact values, unknown/duplicate key rejection, policy defaults, references, undo/redo and save/reopen. Freeze v2 in a separately reviewed completion candidate before the legacy decoder maps to it.

## Second slice — Industrial and security declarations (2026-11-25)

Implemented typed staging declarations in `model/v2.rs` and deterministic semantic validation via `validation::validate_v2_declarations`. These types are deliberately not attached to the active v1 Project root or runtime; they are preparation for the single canonical v2 schema, not a new editable project format.

- Reuse SiemensS7 naming. Loopback is a distinct candidate driver kind, permitted only against an endpoint-free, credential-free simulator with no driver parameters; simulation drivers cannot declare physical commissioning. Commissioning intent and writeConfirmed default false and never constitute authorization.
- Momentary/maintained commands require boolean writable tags; momentary requires positive duration. Setpoints require writable numeric scalar tags. Critical commands require confirmation. Numeric limits are separate from display range; validate exact signed/unsigned widths without f64 coercion, min <= max and positive step. Conservative candidate rejects f32 limit values that would narrow on conversion and integer literals that would round when interpreted as floats. This is an engineering default subject to contract review; no runtime limit enforcement is implied.
- Typed permission and role identifiers share the existing global namespace. Validate nonempty names, unique declaration/reference entries, existing role and permission references, positive configured auto-logout, and screen/node references (including reusable definition nodes). No user/password store, imported trust or permission evaluator.
- Validate the base project before staged declarations. No project mutation, PLC connection or write execution. Unknown fields remain rejected. Seven new synthetic tests cover round-trip staging, v1 rejection of v2-only fields, exact adjacent u64 limits, invalid commands, narrowing, identity collisions, missing and wrong-kind references, duplicate declarations, endpoint/commissioning refusal and invalid base handling. The initial u64 test had an incompatible fractional recipe value in its synthetic base; corrected the fixture, not validation.

Next: integrate these declarations into typed engineering operations and complete action, enumeration, component and expression contracts. Before activating v2, finalize inline serialized fields, v1-specific admission, schema migration, persistence/undo behavior, downstream consumers and publish refusal for unsupported features. Do not claim schema freeze or runtime enforcement yet.

## Third slice — Expressions and enumerations (2026-11-25)

Implemented a fresh Rust candidate for HMI Forge binding expression contract 1, based on read-only inspection of the pinned legacy contract documentation and behavior at 92a612d104693800d7119ee4dc0114636b19002f. No Kotlin source or legacy fixture transferred. Original synthetic vectors exercise arithmetic, precedence, boolean operations, comparisons, conditional selection, text concatenation, escaped text, quoted and dotted references, all documented built-in functions, quality propagation, short circuit, isGood/ifBad, missing/wrong-type values, malformed expressions, nesting and maximum-length chains.

The parser checks UTF-16 source length (1024) and nesting (64). Compilation validates reference existence and static types and returns ordered unique dependency IDs; evaluation accepts an immutable reading snapshot and has no device, write, time or arbitrary-code capability. Nonfinite arithmetic and invalid operations produce BAD with no value. A 1 MiB text input/output limit is an additional conservative engineering bound. Contract 1 computes in f64; the explicit canonical scalar adapter refuses out-of-range or inexact integer conversions, including adjacent u64 values above 2^53, instead of silently rounding. Float32 inputs use their declared width. Adapter refusal must become BAD at the future runtime integration boundary.

Typed enumeration definitions support exact signed/unsigned integer, boolean and string values, unique stable IDs and values, localized labels, optional hex colors, exact read-only lookup and tag mappings with matching data types and read access. Validation checks global namespace collisions including staged security identifiers, locale keys, duplicate mappings, missing references and expression target conflicts. Expressions may target supported read-only bindable catalog properties with compatible result types; direct bindings and writable targets are refused.

Scope limits: staging only, not active v1 schema or an alternate project file. Reusable-instance parameter expression binding, reference remapping during legacy import, additional target types (e.g. color and bounded integer properties), and rendering/evaluation wiring remain separate. Floating-point expression arithmetic is legacy f64, not an exact integer computation engine. Diagnostic wording, Unicode lexer corner cases and JVM/Android floating-point text formatting across all IEEE-754 values are not asserted identical; independent cross-runtime conformance remains a gate before declaring contract parity. No physical writes or permission enforcement are introduced. Enumerations deliberately exclude continuous floating values and compound types pending explicit compatibility mapping. Future v2 integration must retain or explicitly refuse every unsupported legacy field, never silently approximate.

Next: complete typed action and component contracts, then canonical integration with engineering transactions and migration, downstream consumers and the cross-runtime parity gate.

## Fourth slice — Components, actions and initial typed command (2026-11-25)

Added original reusable passive symbol definitions for motor, valve, conveyor, sensor, pump, tank, pipe, thermal indicator and flow indicator. They use existing semantic absolute layout and rectangle/ellipse/text/indicator/numeric display nodes, stable IDs from the shared allocator, explicit read-only typed status/value parameters and no events or device writes. Geometry is a new baseline, not verified legacy visual fidelity or runtime quality rendering. Numeric factory slots initially use Float64, requiring exact parameter compatibility.

Candidate missing-component contracts cover line, arrow, polygon, text input and dropdown. Geometry validates finite distinct coordinates, positive stroke widths, bounded polygon point count and nonzero signed area; arrow heads are bounded by segment length. Text and dropdown inputs validate readable/writable exact tag types, length bounds, enumeration references and localized labels. Existing ProgressBar supports vertical orientation for a future levelIndicator mapping; equivalence is not established. Shapes/inputs are staged declarations without canonical tree placement, catalog rendering or write execution yet.

Added explicit faceplate and industrial-symbol definition classification, mixed ordered candidate action sequences, dynamically resolved startup navigation, typed faceplate arguments/defaults, and validation of event origins, supported event kinds, duplicate handlers, global identifiers and reference types. Existing actions are checked with the existing validator. Passive symbol definitions reject write bindings, nested instances, existing and staged action handlers. Faceplate tag arguments require readable tags and existing typed parameter checks. Startup target resolves the current page, not a frozen id; no navigation is executed. Candidate handlers reject overlap with active handlers pending explicit integration rather than overwriting existing behavior.

First typed engineering command createIndustrialSymbol now creates the reusable definition using the existing atomic ProjectSession transaction, shared allocator, change notifications, rollback, undo/redo and retired-ID rules. Its output is ordinary v1-compatible component data; classification is not persisted by that command yet. Six original component/action test groups and one command regression cover definition validation, round-trip, malformed inputs, references, startup target changes, passive behavior, exact undo/redo and atomic rollback.

Next: integrate remaining staged declarations into the single canonical model and typed engineering commands (including creation/edit/delete/remap semantics, action/shape placement and binding compatibility); then activate schema v2 with strict v1 admission and lossless migration, persistence/schema regeneration and downstream consumer checks. Current schema is still v1. Do not mark v2 frozen or claim UI/runtime/legacy visual parity. The new symbol geometry, conservative input bounds, polygon rules and Float64 slot choice are engineering defaults subject to review.

## Fifth slice — Canonical integration and migration candidate (2026-11-25)

The single Project owns a normalized typed v2 declaration section (industrial, bindings and components groups), validated by the ordinary model validator. Empty groups serialize away. Stable IDs are collected by engineering-core, and SetIndustrialSecurity, SetExpressionEnumerations and SetComponentActions replace typed groups through atomic ProjectSession transactions. Nonempty v2 edits use strict validation; subtree duplication is conservatively refused until reference remapping preserves every v2 declaration. The original symbol creation command still creates ordinary reusable definitions; classification can be applied separately. Candidate primitive/input declarations without canonical tree placement are explicitly rejected on validated load/save/transaction, not silently accepted as detached objects.

The draft branch writes schemaVersion 2 and includes a built-in additive v1-to-v2 migration: original v1 fixtures and v1 schema remain unchanged; migration rejects any root v2 key in a v1 document, including null or empty objects, before bumping the version. Existing unknown-field/duplicate-key rejection remains. Historical v1 fixture comparisons now assert only the version changed. The generated v2 structural schema is committed separately. Persistence tests verify explicit save, canonical reopen, undo/redo and policy transaction rollback.

Downstream scope extended on the existing RUST-05 claim by expected-ref compare-and-swap with overlap checks, before changing consumer files. Existing tag engine refuses nonempty v2 declarations or unsupported schema version before driver startup (returns an empty, shut-down engine and explicit InitIssue). Existing desktop workspace refuses opening/recovering projects with nonempty v2 declarations before replacing current state or deleting recovery, and refuses the new declaration commands at its IPC boundary until its editor supports them. Empty migrated v1 projects remain supported by the existing consumers. These are capability admission boundaries, not a production approval requirement for simulation. Local Rust crate tests cover the runtime refusal; desktop host regression added but native Tauri build is not yet validated locally (offline Tauri dependency unavailable).

This is a schema activation **candidate on the draft branch**, not an accepted or frozen schema. Remaining gates: canonical placement/rendering of missing primitives/inputs, reference-aware copy/remap including expressions/actions/security and symbol classification, downstream desktop admission/compatibility checks, cross-runtime expression parity, exact-head hosted CI and independent review. Do not start legacy decoder mapping until these gates are met. No private fixture/source transfer.

## Sixth slice — Canonical placement and reference-aware duplication (2026-11-25)

Line, arrow, polygon, text input and dropdown are now actual leaf component kinds in the canonical layout tree. Their typed contracts are normalized by the node ID in the same Project, with one matching contract per placed node; missing, duplicate, wrong-kind and orphan contracts are errors. IDs belong to the tree, not to a second declaration. Common catalog properties and event rules apply, while geometry/input data has one typed source of truth. The insertV2Component command atomically allocates or admits a node ID, validates placement and registers its contract. The symbol factory command now also persists its industrial classification. Existing passive symbol validation rejects typed writable input nodes. The original v1 schema and fixtures remain unchanged; migration rejects new component kinds in v1 semantic node/style locations without scanning or rewriting opaque extension payloads. The v2 structural schema was regenerated.

Screen, node and reusable-definition duplication now clone node-linked permissions, expressions, component contracts and action handlers, remapping origins and self-referential navigation/faceplate targets. Screen permissions and definition classifications are copied. Shared tags, roles, permissions, enumeration definitions and external targets remain shared. Dynamic startup navigation remains dynamic. Duplication and moves refuse to lose ancestor/screen permission requirements; cross-definition reparenting is conservatively refused for v2 projects until instance/parameter scope mapping is defined. Raw InsertNode with reassigned IDs cannot copy an existing v2 subtree and bypass declaration copying; use DuplicateNode. Deletion of referenced objects requires explicit removal of their declarations in the same validated transaction rather than silent cascading removal. Undo/redo and rollback are exercised on the canonical snapshot.

Existing desktop workspace and tag engine remain incompatible with these features and refuse activation; detection includes malformed new-kind nodes even if declarations are empty. The desktop IPC rejects typed insertion, classified symbol creation and new-kind style edits until renderer support exists. This does not add a production approval gate to simulation. Model placement is not a renderer implementation or runtime write execution. Prior head b250ada Desktop CI, Tag engine CI and handoff all passed; new head must independently pass its own checks.

Next: downstream workspace/editor/renderer compatibility and explicit capability admission, cross-runtime expression conformance, and independent technical review before freezing the schema. Remaining limitations include cross-definition reparenting, explicit reference-aware deletion workflow and unsupported runtime semantics. No legacy fixture or source transfer.
