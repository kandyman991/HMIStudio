No real projects or private source transferred.

## Implemented

`hmi_legacy_import::import_portable(&[u8])` returns an optional validated canonical `Project` and a deterministic `MigrationReport`. It has no file writes, device access, runtime commands or deployment behavior. Only explicit source versions 1–10 are recognized. The decoder rejects duplicate keys at every level, invalid UTF-8/JSON, oversize inputs (4 MiB), excessive nesting (serde JSON limit), more than 20,000 report leaves or paths exceeding 1,024 bytes. No archives are admitted by this API.

The initial mapping subset covers metadata, explicit startup screen, flat absolute screen dimensions, static labels with explicit text and geometry, visible flags, internal read-only variables with six scalar types and exact typed default values. Legacy Float fields are interpreted at binary32 precision. Source IDs retain valid noncolliding values or are allocated deterministic replacements; the project ID is derived from its input SHA-256, generated root IDs are identified in the ID map. For multi-screen projects explicit valid order is currently required (v5+); ambiguous equal z-index ordering is refused. Default locale is en because no source locale is declared in this subset. No visual fidelity claim.

The report records the input SHA-256, source version, importer version, RFC 6901 paths, disposition, code, severity, message, proposed canonical target and ID map. For well-formed admitted-size inputs, every leaf (including empty containers) is accounted for. If any finding is refused, **no project is returned**. Mapped findings on a refused import describe proposed transformations, not persisted output. Malformed or resource-limited inputs receive a root refusal instead of an unbounded leaf report. The report does not include arbitrary source values, but paths and ID mappings contain source key names/identifiers: keep reports local and review before sharing. No arbitrary source data is copied to extensions. Successfully mapped projects carry `hmiforge.idMap`; adaptive nodes also retain explicitly decoded geometry and validated z-index as inactive design metadata (B.3).

## Explicit remaining work

This is deliberately not full v1–v10 compatibility. Version-number coverage tests use the same supported synthetic subset, not all features introduced at each version. Full source semantic validation, remaining industrial/security semantics (see B.2 below), remaining graphical/layout/binding/enum semantics (see B.3), actions, alarms, assets and themes remain outstanding. Those inputs refuse rather than silently downgrade. Preserve-with-blocking semantics are not available until publishing/runtime refusal is integrated; no partial project is emitted. Revision bundle and runtime package readers with checksum/size/traversal verification, typed engineering import command, sidecar reports and UI integration are also outstanding. No acceptance or completion of REUSE-03 is claimed.

## REUSE-03B.2 — Industrial declarations and reference mapping (2026-11-25)

The predecessor PR #36 head `8458d4574f4cb3a701b8483cbc686ce5592e0e8c` passed hosted Desktop CI 45699525142 and handoff 45699525091. These are predecessor checks only. The RUST-05 reservation remains on the same branch and covers the importer crate.

- New independent Rust mapping module resolves S7, OPC UA and endpoint-free loopback to typed connection declarations, preserving commissioning intent as data only. A strict nonsecret parameter allowlist admits basic DNS/IPv4 S7 endpoints and OPC UA host:port endpoints and explicitly supported security presets. Unknown parameters, URL credentials, unsupported drivers and loopback parameters refuse import; no credential values enter reports or extensions. This is not driver configuration or protocol acceptance.
- A single unambiguous external mapping per variable maps to tag connection/address and compatible access. Read/write requires explicit legacy confirmation and a representable command, with exact type/access matching. Duplicate writable address aliases on the same source, multiple mappings per variable, unresolved references, unconfirmed or write-only access, and writable variables without an external mapping refuse. Every imported external source creates a v2 connection declaration, so the existing tag-engine refusal of unsupported v2 projects remains in force. No runtime changes.
- Numeric engineering-unit symbols are deduplicated deterministically. Momentary commands use the legacy 500 ms default or explicit 100–5000 ms pulse; maintained/setpoint commands require confirmation regardless of the momentary-only legacy confirm flag. Setpoints require min/max; integer limits must be exact after legacy binary64 interpretation and fit the canonical integer type; float32 limits must not narrow. Frozen canonical validation also checks ordering and positive step. No runtime write is enabled.
- Security maps custom permissions, six legacy built-in permission identifiers, roles, explicit grants, anonymous role, minute-to-second auto logout and screen/node required permissions. IDs are allocated globally and references resolved by legacy ID, never display name. No account, password or implied grant is imported. Effective built-in runtime permission behavior, including the maintenance fallback, must be validated at runtime interoperability; this is declaration mapping only.
- Explicit refusal rather than approximating unrepresentable policy fields: critical-command second-confirmation/reason requirements, write-only momentary operation, explicit readback timeout, decimal places and maximum change per write; non-null custom permission description is also refused. Default legacy readback semantics are deferred to runtime compatibility and must be verified before publishing. No schema changes were made. Split endpoints, writable aliases and unsupported configuration/security variants remain refused. Unsupported content continues to withhold the whole project until the planned preservation/publish guard exists.

Validation: 11/11 locked offline importer tests, including five new industrial regression groups (determinism/leaf accounting, exact integer limits and reference/permission failures, pulse/confirmation defaults, OPC UA/loopback, alias and credential refusal). ## REUSE-03B.3 — Components, layout and binding declarations (2026-11-25)

Based on PR #36 predecessor 2d949af. Same retained RUST-05 claim; no canonical model, downstream consumer, dependency or CI policy edits.

- Maps selected component declarations (label, button, rectangle, ellipse, numeric field, indicator) and composite instances. Static typed property allowlist requires explicit supported values; no implicit theme/color substitutions, arbitrary strings in numeric fields or write bindings. Legacy numeric field direct bindings to writable variables refuse rather than converting an operator input to a read-only display. Renderer parity is not established, and component-specific warnings are reported where relevant.
- Maps nested explicit ROW/COLUMN stacks and component slots into canonical flow trees with gaps, padding, sizing bounds and row weights. Placement is unique and complete, source layout IDs are globally resolved, generated root aliases are retired when replaced. Decoded absolute geometry and validated z-index are retained in inactive extensions for design recovery; unknown geometry fields remain refused. Reflow/weight algorithms, fonts and exact sizing are not equivalent by proof; report warning diagnostics. Legacy ADAPTIVE, GRID, ScaleGroup, explicit slot alignment and visibility-driven reflow refuse in this slice. Root design dimensions are retained.
- Maps v6+ reusable composites with static content and read-only BOOL_VARIABLE/TEXT_VARIABLE parameters. Internal direct bindings resolve to local tagParameter references; screen instance arguments resolve to remapped project IDs and canonical validation enforces parameter types and reference validity. Unmapped standard catalog definitions, writable/numeric/value parameters, parameter interpolation, reusable expressions, faceplates and nested parameter forwarding refuse. No claim that a normal full legacy catalog export is supported.
- Maps selected read-only direct slots and contract-1 expressions. Original source is compiled against legacy variable IDs; lexical remapping preserves string literals, function names and numeric exponents, and rewritten expressions are compiled against canonical IDs with matching type and reference sequence. Unknown refs, invalid expressions and overlapping targets refuse.
- Maps v10 standalone enumeration declarations with exact signed 64-bit values, literal labels and supported hex colors. Component-specific enum use is not mapped to a tag-global association: that would change semantics. Such references, theme tokens and unsupported drop-down behavior remain refused.

Local locked offline tests 17/17 (six new groups), Clippy, rustdoc and formatting passed. New groups cover nested layout and refusal of unknown geometry/visibility semantics, static/reusable parameterized composites, direct bindings/shapes, expression ID remapping and exact enum values, duplicate/unknown references and leaf accounting. Synthetic-only. Frozen schema SHA-256 b7d49729750bea7a598afa89f64fa57598d5603a88d0fba0dd664abd75ab2738 unchanged. No native or runtime parity acceptance. The importer returns data only, and safe publication refusal for imported approximations must be integrated before exposing imports in the engineering UI. Full technical review and exact-head hosted CI remain outstanding.
